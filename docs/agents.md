## Auto-mejora (como se mejora un agente o una skill)

Este registro es de solo lectura para los agentes: se regenera con `agents-registry build`, nunca se edita a mano. El historial real vive en git (cada commit de un agente o skill es una version) y en el feed de eventos (`kind=agent-change`).

Protocolo para proponer una mejora sobre un agente o una skill:

1. Abrir un ticket con `rig ticket add <ID> --project dotfiles --title "..." --area meta --owner supervisor`.
2. En el ticket, declarar el motivo y la evidencia: fallos o loops repetidos (sesiones en `opencode.db`), consumo alto (`agents-registry show <nombre>`), un hueco de razonamiento visto en una conversacion exportada, o un check de `verify` roto.
3. Declarar la verificacion: que check/`verify` demuestra la mejora.
4. Integrar el cambio en una silla (worktree + branch `ticket/<id>`); al mergear, `agents-registry build` registra la version anterior y la nueva y emite el evento `agent-change` con el motivo.
5. Cerrar el ticket con evidencia (`rig ticket done`).
